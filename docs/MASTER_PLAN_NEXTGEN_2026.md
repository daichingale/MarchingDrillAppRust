# DrillForge Next-Generation Master Plan v2.0
**策定日:** 2026-10-23 / **更新日:** 2026-10-24 / **状態:** 提案・レビュー用 / **対象:** デスクトップ・モバイル・共同編集・オフライン制作

> **目的:** Pyware 3D の複製ではなく、マーチングの構想→ドリル設計→動作検証→演出→現場練習→改訂→配布を、正確・高速・安全につなぐ独立したオープンソース製品を作る。
>
> この文書は「次にどこを改善するか」の**製品横断の生きた計画**。既存の規範である [90-integration-roadmap](design/90-integration-roadmap.md)、個別の [design/](design/)、[PRODUCT_QUALITY](../PRODUCT_QUALITY.md) の確定した内部型や保存規約を一方的に上書きしない。矛盾した場合は ADR と回帰テストを作って裁定する。本文に「完成」と書いただけでは完成にならない。

## 0. 設計の要点と決定区分

### 確定済みの土台（今回も維持）
- **Rust を中核**とする Windows / macOS / Linux デスクトップ、GPU は wgpu、UI は egui。共有ロジックを UI、OS、GPU から独立させる。
- **完全 OSS / 機能課金・ライセンス認証なし**。現在のワークスペースは \`MIT OR Apache-2.0\`。有償認証を追加しない。
- **ローカル最優先**: 編集、アニメーション、保存、PDF/CSV、実装済みの基本解析はネットワークなしで利用可能とする。同期とクラウド機能は任意。
- **単一の権威ある座標・時刻**から 2D、3D、座標表、印刷、映像、練習ビューを導く。重要な編集は逆操作を持ち、保存は検証・原子的置換を行う。
- **商用ベンダーの独自バイナリ形式・UI・アセットを複製しない**。公開仕様または利用者自身が合法的に書き出した一般形式を相互運用の基本とする。
- 初期構成の性能/正確性は [PRODUCT_QUALITY](../PRODUCT_QUALITY.md) に従う。「既存の実装証拠」と「実機で検証済み」は分ける。

### 今回提案する重要な設計判断（ADR 承認前は未確定）
1. **編集は「プレビュー→検証→コミット」のトランザクション**に統一する。UI のドラッグも AI の提案も、同じ編集コマンドを使う。
2. **タイムラインの意味を拡張**し、位置・移動経路・向き・楽器操作・カラーガード演技・プロップ・照明を別トラックとして整合させる。ただし新しい保存フィールドは移行/Undo/同期計画の承認まで追加しない。
3. 共同編集の**点単位 LWW は試験段階のモデル**として維持するが、図形の一括変形やセット挿入にはそのまま適用しない。範囲トランザクション/競合提示を導入する。
4. AI は**外部入力として不信頼**。許可された型付き提案のみ受け取り、制約検証、差分表示、ユーザー承認を経て反映させる。
5. スマホは当面 **練習ビュー・座標確認・限定的な共同編集に最適化した Web/PWA** を優先する。ネイティブ化は端末計測・配布要件を満たしてから。
6. **校内利用・未成年者の個人情報を最小化**。公開リンクから本名・学校情報・譜面・音源を漏らさない。同期は明示的に有効化したルームでのみ行う。

## 2. 誰の、どの仕事を、どこまで支援するか

| ペルソナ | 最重要ジョブ | 最高の体験 |
|---|---|---|
| ドリルデザイナー | 数百人のセット/経路を速く正確に完成させる | 操作1つで隊形を調整し、全ての人数ID/カウントが守られる |
| 指導者・セクションリーダー | 曲に合わせて安全に合奏・移動を指導 | 今日の範囲を選び、問題と個人座標を即配布 |
| 生徒・演者 | 自分の位置、進行方向、前後の基準、動くタイミングを知る | 自分だけの動線がスマホで分かり、オフラインでも見られる |
| 演出家・スタッフ | 客席から見た構図、小道具、タイミングを比較 | カメラと演出を含むショー案 A/B を同じ時間軸で比較 |
| 学校の IT/大会運営 | 安全に導入・共有し、古い PC でも使う | インストール困難な PC でもポータブルで動き、データを漏らさない |

**最初に完璧にする縦の体験:** 30m 屋内フロア → 80人配置 → 16カウント × 8セット → 音源同期 → 経路/衝突確認 → A4練習プリント → 演者別スマホ確認 → 改訂差分の配布。これを説明なしに通せることが「機能豊富」の基準。

## 3. 6つのプロダクト・ピラー

### A. Design — ドットと図形を極める
- 選択：単体、矩形、投げ縄、パート/属性/サブセット/名前、空間フィルタ、選択履歴、ロック/非表示の明示。
- 描画：直線、等間隔アーク、円、楕円、ブロック、螺旋、ベジェ、自由線、文字アウトライン。全ツールで**点数固定と配置順**を事前表示。
- 変形：移動、回転、拡縮、対称、フィット、列/行の等間隔、曲線へ吸着、混合図形モーフ、アンカーでの変形。
- **形の編集と演者の割り当てを分離**: 形状を変えても演者の ID を失わず、入れ替え案は実行前に示す。
- スナップ：メートル/ヤード/歩幅の単位、最小目盛り、縦横独立、演者間隔、基準線、中心/左右対称、相対配置。
- 編集 UI：ドラッグ前後の影絵、移動量の数値入力、Alt 複製等のキー操作、Esc キャンセル、確定1 Undo、同一ツール内の局所履歴。
- **優先課題**: ポインタが滑る・座標がズレる・ハンドルでドットが隠れる・狭い画面でパネルが重なる問題を、見た目でなくテストで潰す。

### B. Motion — 静的なセットから、動く作品へ
- 既存の \`RouteShape\`、\`Gate\`、\`Easing\`、\`SetCounts\` を**唯一の移動モデル**とする。
- 位置に加え、**Facing/Body Orientation**（正面・固定方位・進行方向・後退・スライド/クラブ）を独立したキーフレーム系列として設計する。移動方向＝体の向きと決めつけない。
- Follow the Leader、Counter March、Pinwheel、Ripple、隊列追従は単なる座標のコピーでなく、**移動時間・個人ID・経路長・可動域**を保持する操作として定義。
- 歩幅評価は直線距離でなく**実経路の弧長**と有効移動カウントで計算。身体の向き、装備、逆行、安全余裕を別係数として表示する。
- 衝突は各整数カウントだけでなく**カウント間の連続軌跡**を対象にする。検出区間、最小距離、対象ID、原因と修正提案を示す。
- 瞬間移動や壊れた接続は**Continuity Error**、実行可能だがきつい移動は**Difficulty Warning**として区別。
- 提案は「対象演者」「評価対象カウント」「変えるもの」「変えないもの」の宣言が必要。**同じ入力で同じ候補**になる決定論を原則とする。

### C. Stage — 音楽・演技・舞台を時間軸で統合
- Timeline を DAW の考え方に近づけ、\`Position/Route\`、\`Facing\`、\`Equipment\`、\`Prop\`、\`Visual/Lighting\`、\`Camera\`、\`Audio/Tempo\`、\`Marker/Comment\` の**トラック**を想定する。
- トラックの再生/書き出しは全て **ShowTime = 整数カウント + 有理数サブカウント** を基準にする。可変 BPM ⇄ 秒の写像は高精度な既存 \`TempoMap\` に任せる。
- 演者に付属する楽器や旗は**演者IDへひも付く別アニメーション**。振り、投げ、受け、楽器上げ下ろしを時系列で表示。
- ステージの小道具は通路や接触範囲を持つ。3D素材、図形、テクスチャは利用者所有か再配布許可が明示されたものだけ。
- カメラは「全体・客席中央・実際の審査席・演者追従・任意席」。客席への死角やプロップの遮蔽もプレビュー。
- 音楽イベントの推定（アクセント、フレーズ）は**参考候補**。元音源とテンポ設定を黙って書き換えない。
- 2D の PDF/動画は CPU 参照描画、3D は GPU の特性に応じて視覚一致を検証。Blender 連携を高品質映像の出口とする。

### D. Intelligence — AI が提案し、デザイナーが決める
- \`Intent\`（例「トランペット16名、次の16カウントで2重円→V字」）→ \`CandidateGeometry\` → \`CandidateAssignment\` → \`CandidateRoutes\` → \`ConstraintReport\` → \`PreviewDiff\` → \`EditBatch\`。
- **AI は任意**: オフライン時は規則・探索・最適化で基本提案が動く。ローカル LLM（例: Ollama）や OpenAI 互換 API は構造化命令の解釈支援に限定し、外部送信は明示同意。
- 提案に必須の制約: 固定演者、固定セット、立ち入り禁止、前進/後退の最大歩幅、最小間隔、セクション群の連続性、フィールド境界、持ち物の占有幅、カウント上限。
- 最適化は多目的：総移動距離、最大個人負荷、交差数、音楽的アクセント、形の読みやすさ。**審美性スコアは代理指標**と明記し、目的関数・重みを画面に見せる。
- 全候補に評価指標、違反理由、タイムアウト、再実行種/バージョンを添付。内部モデルが「美しい」と断言しない。
- AI/プラグインの入力（譜面タイトル、コメント、ファイル本文）は不信頼。外部 URL 実行、任意ファイル読み取り、無断アップロード、コマンド実行を許さない。
- ユーザーが選ぶまでは**ドキュメント無変更**。候補採用は一つの Undoable \`Edit\`、キャンセル/競合時は完全ロールバック。

### E. Rehearsal — 実際の現場で役立つ
- **練習モード:** 今日のセット範囲、今日の編成、教師/パートリーダーの注釈、音源・メトロノーム・カウントをワンタップにまとめる。
- **個人モード:** 自分の位置、次に進む方向/距離、曲のどこか、近隣の基準演者/基準線、動線、停止点を表示。静的配布はネット不要。
- **欠席対応:** 欠席者を作品本体から削除しない。\`RehearsalRosterOverlay\`（その日の仮編成）として欠員を示し、穴埋めは**提案**として分離。正式適用は別操作。
- **配布:** A4のセット図、演者別ドリルブック、Production Sheet、今日のチェックリスト、観客向けショー紹介、先生用リスク一覧。印刷テンプレートは独自規格とする。
- スマホは画面拡大、低通信量、横/縦画面、タップ誤操作抑止を最重視。「作品編集」と「練習で見る」は明確に分ける。
- QR/共有リンクの権限・有効期限・取り消しを表示。未成年者の名前は原則匿名/表示名で扱い、公開リンクの既定は「閲覧なし」。

### F. Platform — 堅牢な土台
- \`.drillproj\`（バージョン付き、自己記述、保存前検証、ハッシュ付きアセット）を正規保存。JSONは互換/デバッグ用途として維持。
- 既存の \`DisplayList\` から画面/PDF/ビデオを派生。変換アルゴリズムを出力形式ごとに重複実装しない。
- 同期は現行 LWW per-dot を起点に、**図形操作・セット挿入・全体テンポ改変を複数ドットの独立書込へ分解しない**。
- ネットワークなしで主要作業を完結。権限・共同編集・オンラインモデルは別プロセス/非同期ジョブで隔離。
- 署名と最新依存のセキュリティ検査が通らないビルドを一般配布しない。更新とロールバックを実機検証する。

## 4. 画面 / ワークスペース構成（詳細は別紙）

1. **Design:** フィールド最大化、文脈に応じたフローティングツール、右側プロパティ、下部タイムライン。左側は必要時だけセット/パート一覧。
2. **Motion:** ドットの移動経路・進行方向・カウント区間を編集。経路を選ぶとゲート・イージング・必要歩幅・衝突を同時表示。
3. **Stage:** 2D/3D カメラ、プロップ、衣装、照明、映像書き出し。重いレンダーは別ジョブに切り離す。
4. **Review:** 3D客席 / リスクマーカー / 修正前後の差分 / 案 A/B 比較。解析結果には根拠と深刻度を示す。
5. **Rehearsal:** 大きいカウント表示、範囲ループ、個人/パート表示、配布。プロジェクターとスマホから読みやすい。
6. **Beginner:** 4段階「会場→人数→場面→確認」。高度機能を隠すだけで、保存データや編集エンジンは同じものを使う。

**見た目の原則:** 明るい/暗いモード、色に依存しない図記号、操作対象の拡大、100–200% DPI、ショートカットの再設定、異なる解像度の複数ディスプレイ、JA/EN双方の余白を持つテキスト。競合の UI を画素/配置で模倣しない。

## 5. 時刻・座標・編集の不変条件

| ID | 変更不可能な性質 | 検証 |
|---|---|---|
| INV-01 | 同じ \`PerformerId\` は、セット・トラック・練習配布で同一人物を指す。並び替えで ID は変わらない | 追加削除・複製・マージ・Undo/Redo |
| INV-02 | すべての \`SetId\` は一意。過去の版のセット番号ではなく ID により参照する | バージョン移行、並び替え |
| INV-03 | 座標は有限値、フィールドに対して有効、\`Unit\` は Yards/Meters を必ず記録 | 出力/再入力、境界/NaN/無限大 |
| INV-04 | \`5m\` と \`5yd\`、\`8-to-5\` と \`5m/8歩\` を混同しない | 幅・歩幅・PDF/CSVゴールデン |
| INV-05 | 各サンプル時刻で \`Route/Gate/Hold\` の開始点・終点・評価結果が再生と一致 | カウント境界、曲線、停止、遅延出発 |
| INV-06 | 1回のユーザー意図（ドラッグ、図形変形、AI候補採用）は1つの Undo 単位 | 10,000編集、途中キャンセル |
| INV-07 | 保存ファイルは破損・未対応将来スキーマを黙って解釈しない。元ファイルを残す | 切断/電源断/未知フィールド |
| INV-08 | 重い操作とファイル書出しがフレームループを長時間停止させない | 最大負荷UI待ち時間ゲート |
| INV-09 | プレビュー、AI候補、練習日の欠席は採用前に正式作品を変更しない | 確定前のハッシュ同一 |
| INV-10 | 同期競合や旧形式の曖昧な情報を黙って推測・上書きしない | オフライン復帰・二重編集 |
| INV-11 | 音源/映像/素材の権利を推定しない。表示/配布時に同意と必要範囲を確認 | 外部公開・配布テスト |
| INV-12 | 画面・帳票・動画の座標変換は同じ FieldMap/評価モデルを使う | 中心点/端/方向/回転テスト |

**時刻系の定義:** \`global_count\` はショー上の単調に増えるカウント、各セットの \`moves+hold\` が進行尺。楽器/旗/照明などの副トラックは整数カウント + 合理的に上限を設けたサブカウント精度（最初は 1/8）で同期し、音声とエンコード時刻への変換は f64 の TempoMapを通す。内側の 2D/3D 幾何評価で f32 を使う現行仕様は維持し、保存型の変更は ADR を必要とする。

## 6. コア構造と責務

\`\`\`text
Desktop egui                  Web/PWA practice / limited editor
     |                                    |
     +-----------typed intent-------------+
                         |
                 Application controller
                         |
             Preview/Validate/Edit gateway
                         |
    +--------------------+----------------------+
    |                    |                      |
 drill-core          drill-interop          drill-sync
 IDs/geometry        open formats          validated room ops
 count/routes         mapping/diff          merge/conflict UI
 edit/history         musical import       online OPTIONAL
    |                    |                      |
    +---------- revisioned immutable snapshot -+
                         |
         render / audio / export / 3D / clinic
                         |
            background bounded jobs
               |              |
           local AI*       plugins*
             opt-in        sandboxed
\`\`\`

- **drill-core** は geometry, time, invariants と純粋な計算の所有者。UI/GPU/OS/HTTP を依存させない。
- **drill-app** は UI・入力・仕事の進行・状態表示に集中。新しい大きな計算を \`app_state.rs\` に直接書かず、既存モジュールを使う。
- **drill-render** が正規表示中間形式（DisplayList）を生成し、GPU/CPU/PDF が消費する。
- **drill-audio** は実時間音声ホットパスとデバイス回復。**drill-export** は決定論的生成/エンコードを担当。
- **drill-project** はスキーマ移行・バックアップ・復旧。**drill-jobs** は進捗/中断/期限/リビジョン照合。
- **drill-interop** は公開形式のパース、曖昧性検出、プレビュー・差分。独自形式の非公開解析は行わない。
- **drill-sync** はリアルタイム共編の限界と契約を記載し、\`drill-presence\` は閲覧状態を分離。
- **drill-web/mobile-viewer** は最小個人データを受け取り、表示に必要なだけキャッシュする。
- \`*\` AI/プラグインは追加しても**基本編集の必須依存にしない**。新クレートは「本当に独立ライフサイクルが必要か」を ADR で確認してから作る。

### 6.1 型付き編集提案の契約

\`\`\`text
EditIntent {
    actor, base_document_revision, target_ids, time_range,
    constraints, deterministic_seed, requested_change
}
  -> CandidateSet {
       variants[], metric_explanations[], warnings[],
       preview_diff, immutable_snapshot_hash
     }
  -> ValidateCandidate {
       finite_coordinates, valid_ids, scope_conflicts,
       geometry_invariants, performer_limits,
       unit_consistency, data_policy
     }
  -> Commit(EditBatch) | Reject(reason)
\`\`\`

上記は**概念インターフェースであり、現行 Rust 型の宣言ではない**。AIが生成したテキストを直接 \`Edit\` に逆シリアライズしない。UI表示と確定の間で \`base_document_revision\` が変わったら提案を無効化して再評価する。変更前スナップショットとハッシュを差分表示/一括Undoに用いる。編集ログへはモデルのプロンプト本文を保存しない。

## 7. マルチデバイス/共同編集の安全な仕様

**v0:** 現行 \`drill-sync\` は点およびセットの情報を Lamport stamp + LWW で競合解決。2人が異なる点を動かすには軽量。ロスター全体の再割当、図形の一括変形、セットの挿入/削除、テンポやプロジェクト設定の一括更新には整合性保証が不足する。

**v1（採用案）:** 1人のドラッグは途中状態を presence/preview として伝え、確定した \`EditBatch\` に対象集合・更新範囲・基準リビジョン・競合方針を付ける。別々の点への操作は自動統合、同じ点/同じ時間範囲は差分を示し、意図単位で「再適用／相手の版を採用／別案として保存」を選べる。セット削除・名簿改変には接続中の編集者へ通知する。

**v2:** 不安定な通信からの復帰時にローカル操作キューを再検証。スキーマ互換性と資産ハッシュを確認し、暗黙に欠落データを上書きしない。形式的な CRDT 導入は必要性が示されてから検討する。

**セキュリティ最低ライン:** 推測不能な共有秘密、閲覧/編集の別権限、失効/退出、TLS(リモート)、サイズ/頻度制限、投稿者ごとのログ/負荷制限。教員が明示的に共有した場合だけ音源や名簿情報を送る。単なる室番号を認証に使えると仮定しない。ローカル練習ビューは接続なしで読むことができる。

## 8. Pyware 3D / 3DX との比較指針

公開機能（2026-10-21 公開の 3DX v1.0.9 Beta 6 を含む）から、確認が必要な操作を抽出する。ただし**機能の有無と品質を混同しない**。詳細出典：
- https://www.pyware.com/3dxbeta/ （3DX Beta 6, 2026-10-21）
- https://www.pyware.com/3d-pricing/ （版ごとの提供機能）
- https://www.pyware.com/mobile-editor/ （スマホ編集の例）
- https://www.pyware.com/updates/ （3D 11 更新履歴）

| 競合で参考になる仕事 | DrillForge の独自の差別化 | 検証案 |
|---|---|---|
| Morph / Paste / Splice | どのID/時刻が変わるかを示す **トランザクションプレビュー** | 途中挿入でも前後の連続性・保持の崩壊がない |
| Count Track | 音楽・動線・向き・演技を別トラックで編集 | 可変BPM/部分ループ/カウント間イベント |
| Stride / Collision / Continuity Clinic | 物理距離・移動可能性・安全余裕を別々に説明し自動修正は承認式 | 実測・故意の衝突/偽陽性と照合 |
| Visual Sequencer | 役者ごとのモーションイベントを構造化/再利用可能 | 旗投げ/楽器挙上/時間差が動画と一致 |
| Multi-display | 画面ごと独立した見え方/パネルとラボ検証 | mixed DPI, 複数3Dウィンドウ、長時間描画 |
| Mobile editor | 生徒の個人練習に特化し、端末/通信負荷を軽減 | 端末オフライン・範囲配布・誤編集ゼロ |
| Tutorials | 実際のワークフローに沿う段階的ガイド + Undo可能な練習プロジェクト | 初心者が説明なしに練習プリントまで到達 |

互換戦略は、合法的に入手した一般形式を優先し、正式な公開仕様のない他社バイナリを自動解析しない。競合の UI/画像/フォント/衣装などをコピーしない。

### 着手しないこと（当面）

## 11. 運用・開発プロセス

- **Source of truth:** 現在コード+テスト > 現行のADR/ドメイン規約 > 製品横断マスタープラン > Issueアイデア。将来案を実装済みと混同しない。
- **機能追加テンプレート:** ユーザー問題 / 代替案 / ドキュメント変更 / 編集-Undo契約 / 保存影響 / 同期影響 / 性能負荷 / セキュリティ / JA/EN / 受入テスト。
- **PR必須:** モデル変更は新旧フィクスチャ、失敗時動作、ドキュメントの差分。UI変更は小画面・日本語・ショートカット・操作戻し。
- **AIで作るコードも同じCIゲート**。自動PRの自動マージはしない。大量のコード生成より1つの縦断ワークフローの完成を優先。
- **計測優先:** 1) プロの操作手順 2) 実際のWindows学校PC 3) macOS / Linux 4) AMD/Intel/NVIDIA GPU 5) スマホ低価格機。
- **配布対象・運用者:** マスタープランは公開できるが、現場の個人情報や著作物を含むフィクスチャは公開リポジトリに入れない。
