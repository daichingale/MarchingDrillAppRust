# DrillForge Interaction Spec — NextGen 2026
**状態:** 機能設計案 / **本体:** [MASTER_PLAN_NEXTGEN_2026](../MASTER_PLAN_NEXTGEN_2026.md)  
**目的:** 現場で「設計者が間違えない・操作に迷わない・なめらかに直せる」ことを、見た目より先に保証する。

## 1. UXの非交渉ルール

1. **常にフィールドを最優先。** パネル/バー/ツールチップが演者や編集ハンドルを遮ったら自動退避/折り畳み。狭い画面では片側パネルを一時オーバーレイへ。
2. **選択対象が最も目立つ。** 選択済み、ロック、非表示、読み取り専用、同時編集競合は形・線種・文字で区別する（色だけに依存しない）。
3. **操作前に結果を予告。** スナップ、モーフ、番号再割当、挿入、ルート変更は、適用前に現在/候補を重ね、変わる人数・カウント・警告の増減を示す。
4. **どこでも同じ Undo/Redo。** 1つのまとまった意図を1 Undoとし、Escはプレビュー破棄。ファイル保存はUndoの意味を変えない。
5. **直接操作 + 精密入力。** 画面上をドラッグして操作できる一方、座標や移動量はキーボードから数値入力できる。
6. **日本語優先・英語同等。** 略称/音符/ヤード表記をそのまま文章に混ぜない。初回に「メートル/ヤード」「日本の屋内/海外フィールド」を選択可能。
7. **処理の待機を隠さない。** 100msを超える非同期計算には進捗/キャンセルを表示。古い編集結果は revision が異なれば採用しない。
8. **指導者・生徒への配布は誤変更ゼロ。** 演者向けページの既定は閲覧専用。編集に入る導線を厳密に区別する。
9. **機能は見つけられる。** 常用操作は画面上、専門操作は検索可能なコマンドパレットとヘルプから到達。
10. **既存キーバインドを壊さない。** 追加ショートカットは重複検査、修飾キーの優先順と文字入力中の無効化を維持。

## 2. ワークスペース

### 2.1 Design（既定、詳細モード）

```text
+----------------------------------------------------------------------------+
| ☰ File Edit Arrange Set    [project] • / ⚠     [Search / ?]     [Share] |
+----------------------------------------------------------------------------+
| [Select] [Lasso] [Move] [Line] [Curve] [Morph] [Rotate] [Snap] [View]     |
|                                                                            |
|  FIELD (continuous canvas; projection & axes always consistent)           |
|               A01     A02     A03                   [context bar]          |
|                    \  preview route                                          |
|  left mini-outline (optional)                    right inspector (on demand)|
|  Sections • Sets                              Position / Shape / Motion    |
|  (collapse on small displays)                  exact numbers & warnings    |
|                                                                            |
+----------------------------------------------------------------------------+
| Transport ◁ ▶  Count: 034/480 | Loop | BPM 132 | Waveform                   |
| Count ruler  | S01......S02......S03...... | selection / tracks           |
+----------------------------------------------------------------------------+
```

常用ツールの意味:
- Select: 演者単体・複数・囲みを選択。フィールド空白からドラッグで矩形選択。選択済みドットをドラッグすると Move。
- Quick Arrange: 整列・等間隔、ミラー、数値による距離設定。2名以下で無意味な操作は disabled + 理由表示。
- Shape: 形状を作っても**適用人数・割当順序**を先に説明し、連続選択時の並びを明示。
- Motion: セット間の曲線/ゲート/ホールドを編集。今のセットが最後なら「次セットを作成」と案内する。
- Grid: メートル/ヤード選択・標準歩幅/基準線/屋内ステージの縮尺を選ぶ。既存の座標を勝手に物理変換しない。

### 2.2 Motion

フィールドに「開始ドット（実線）」「目標ドット（破線）」「経路（色+点線区別）」「出発/到着マーカー」を重ねる。
- カウントのスライダーは左右ドラッグ、`<`/`>` ではなく、ユーザーに分かる前/次カウント操作とズームを提供。
- 現在カーソルの`global_count`、`set/local_count`、`BPM`、`MM:SS.mmm` を同時参照。
- **1人選択:** ルート点・出発/到着・歩幅・向きを表示。
- **複数人選択:** 共有スタイル、適用範囲、各人の差分と最大負荷/警告を表示。
- 複数ツール中の操作モードは `Idle → Previewing → Validating → Commit/Reject`。ツール切替/文書変更時は未確定プレビューを破棄。

### 2.3 Stage

同じ ShowTime で 2D, 3D, Seat view, Camera track を表示。
- プロップと演者が物理的にぶつかる場合、表示専用の透過表示と解析マーカーを重ねる。
- グラフィック装飾/照明プリセットは本体のドリル計算を変更しない。
- 衣装や装備モデルを読み込めない場合は汎用シルエットに戻す。音源欠落や3D素材欠落でプロジェクトを開けない状況を作らない。
- 動画書出しは解像度/フレームレート/カメラ/尺/バックエンド/依存ツールの事前検査を実施。

### 2.4 Review

```text
+---------------------+--------------------+
| BEFORE (set 5)      | AFTER (proposal)   |
| path + collisions   | path + updated     |
+---------------------+--------------------+
| Diffs: 18 performers • 4 crossing warnings reduced • 2 new stride warnings |
| View metrics | [Keep old] [Try other] [Apply as 1 edit] [Cancel]            |
+-------------------------------------------------------------------------+
```
- `Collision / Continuity / Stride / Field bounds / Obstruction` のカテゴリを異なるマーカー形状で示す。
- 解析は`severity`と「何を測ったか」を提示。**審美/安全を保証しない**旨を明示。
- 「この警告の修正案を見る」→該当者のみ選択→差分プレビュー→一括 Undo 可能な採用。

### 2.5 Rehearsal / Beginner

**Beginner:**
1. 会場（30m体育館/50m屋外/カスタム）
2. 編成（80名サンプル/名簿CSV/ゼロから）
3. 場面（既存隊形選択/ドット編集）
4. 再生・配布（位置/カウントを確認→練習用プリント作成）

**Rehearsal:** 大型カウント表示・曲の再生/ループ・パート別ハイライト・今日の警告・QR配布を主要操作にする。体育館のプロジェクターで後方から読めるサイズのコンパクトな画面を別ワークスペースとして保持。

## 3. 操作の状態機械と編集契約

| 状態 | 入力 | 動作 | 失敗時 |
|---|---|---|---|
| Idle | 演者をクリック | PerformerIdで選択、番号が変わってもIDは保持 | 無効IDは無視・警告 |
| Selected | 複数ドラッグ | スナップ付きプレビュー（Documentは変更しない） | Escで破棄 |
| Previewing | 数字を入力 | 候補形状の再評価。禁止点/衝突を検出 | エラー理由・現在位置維持 |
| Previewing | 確定 | 既存revisionを照合し`EditBatch`適用 | revision不一致で再プレビュー |
| Committed | Undo | 編集操作の完全な逆操作を適用 | 変更できなければ操作不成立、黙殺しない |
| Editing / Sharing | 共同編集競合 | 重なるID+時間+属性の差分を表示 | 人手で選択、保存版は保護 |
| Playing | 手動ドラッグ | 一時停止/プレビュー中の編集ルールを明示 | 無意識に録画/音源を変更しない |

**ID vs index:** UIの `BTreeSet<usize>` 等の内部選択実装を段階的に `PerformerId` へ統一する。描画向け索引は任意時点の `Document` から解決し、文書の並びを編集した後は失効させる。これは v2 の重要な安全課題。すべての即時置き換えを要求せず、小さなPRで移行する。

### 3.1 スナップ/座標操作の決定表

| ユーザー操作 | 初期設定 | 結果 |
|---|---|---|
| ドラッグ | グリッドにスナップ ON | 現在の単位・刻みと原点に合わせる |
| Shift ドラッグ | 水平/垂直などの軸拘束（キー変更可能） | 軸制約とスナップを併用、最終点を数値表示 |
| Alt ドラッグ | 複製 / 明確な短い操作ヒント | コピー元は移動しない。演者複製はID/全セットの扱いを先に確認 |
| 右クリック/ロングプレス | Context action | 座標、距離、選択追加、ロック、レビューへの移動 |
| 精密座標入力 | 数字の単位明示 | メートル/ヤードを黙って自動変換しない |
| ドラッグ取り消し | Esc | 文書ハッシュ/Undo履歴が操作前と同じ |

Alt、Shift、Ctrl/Cmd の具体的な割り当ては既存の `commands` と矛盾しないかテストし、利用者設定で変更可能にする。

## 4. カウントトラックと音源の UX

- 縮尺を「全曲」「セット」「小節」「1カウント」「1/8カウント」に切替。
- メインのページ/セット境界は動かさず、表示行を上に増やす。再生マーカーが長いショーでも迷子にならない。
- ソングの開始オフセットとテンポ変化は別に見せる。音源をストレッチしない既存方針を保つ。
- 音符/テンポ候補は実際に書き換える前にプレビュー。MIDI/MusicXML は既存のテンポと差分表示。
- 音楽/アニメーション/紙出力で `Set 3, local 16` と `Set 4, local 0` が同じ瞬間を指す場合も、一義的な境界規約を明記して重複/欠落を防ぐ。
- スマホ表示へは印刷物と同じセットID + カウントマッピングを送る。

## 5. 画面サイズ・入力装置

| 環境 | 最適化 |
|---|---|
| 1366×768 学校ノートPC | 片側だけの情報パネル、フィールド確保、ショートカット中心、タッチ小ボタンを押しやすく |
| 1920×1080 / 2560×1440 | 2D編集+インスペクタ+複数トラックを常時表示可能 |
| 2画面・異DPI | 画面ごとの倍率、パネル復帰、座標のピクセル精度、全画面マルチウィンドウの負荷計測 |
| iPhone/Android PWA | 個人ビュー、今日の範囲、左右手用操作、縦/横、圏外キャッシュ |
| iPad / ペン | ピンチズーム、スタイラス配置、手のひら誤反応防止、限定編集 |
| キーボードのみ | Tab, Enter, Esc, コマンドパレット、座標入力、選択移動、カウント移動 |
| スクリーンリーダー | 意味あるラベル、警告読み上げ、色以外のステータス、フォーカス可視 |

## 6. 誤操作からの復旧

- スナップの計算ミス・曖昧な単位・境界外配置は**入力時点で**通知し、静かに座標を書き換えない。
- 自動保存はドリル本体だけでなく必要な参照アセット/版情報も安全に記録。保存と復旧UIは混同しない。
- 外部音源未検出、3Dモデル未検出、GPU失敗時はコンテンツを失わず汎用表示へ。
- 1つのAI提案/ルート最適化が15秒以上かかる場合も、出力候補を勝手に採用しない。進捗とキャンセルを表示。
- ネット切断時は明確な「ローカル編集」「未送信変更」「読み取り専用」状態を表示。同期のまま無限待ちしない。

## 7. 受け入れ試験シナリオ（現場で測る）

| テスト | 成功条件 |
|---|---|
| NEW-01 初回80人作成 | 会場を選び、セットを増やし、音源を同期し、ループ再生まで迷わない |
| NEW-02 精密移動 | 同じ座標/単位入力で画面と印刷が一致し、Undo/Redo後も変わらない |
| NEW-03 複数選択 | 80人から15人を箱選択→等間隔→キャンセル/Undo、他の人は不変 |
| NEW-04 曲線経路 | 個人の曲線・遅延出発・holdが整数/サブカウントごとに一致 |
| NEW-05 衝突警告 | 衝突点とカウント間の最近接が説明でき、関係ない演者は修正されない |
| NEW-06 A4練習プリント | 今日の3セットをA4出力し、日本語・大きな記入/座標欄・演者IDを保持 |
| NEW-07 スマホ練習 | QRを使って本人のセットだけ見られ、切断後も閲覧可能 |
| NEW-08 共同作業 | 2人で別の点を動かすと自動統合。同じ点を動かすと警告・復旧手段あり |
| NEW-09 読み込み破損 | 過去版/不明版/破損/欠落資産で原本に影響なく復旧または明示拒否 |
| NEW-10 素材と著作権 | 公開予定の音源/写真/モデルを自動的に送らない。私有データは既定で非公開 |
| NEW-11 端末間 | Windows (100/150/200% DPI) とmacOS/Android/iOSでグリッド中心・向き・ラベルを確認 |
| NEW-12 実機60fps | 長時間でメモリ増加なく、編集操作の入力遅延・描画時間を計測 |

操作実験は成功・失敗を動画と観測表に残し、達成できなかったケースを Issue に起票する。**実装済みというだけでは UX 完了ではない**。

## 8. 開発への実装指示

- 現行 egui / Rust の構成を優先し、画面だけ別フレームワークに置き換えない。
- 新機能の契約は「意図」「プレビュー」「コミット」「Undo/Redo」「保存」「シンク」「輸出」を通す。
- `crates/drill-app/src/app_state.rs` の巨大化を避け、小さな `ui`・`controller`・`core` の差分に分解する。
- UIの文字は登録済み JA/EN メッセージカタログへ。過去の `docs/MESSAGE_CATALOG.md` は移行当時の監査資料なので再生成で上書きしない。
- スクリーンショット、ローカルシナリオ、リグレッションゴールデンをレビュー可能なPRに添付する。
